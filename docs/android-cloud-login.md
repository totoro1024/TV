# Android TV 统一网盘登录

2026-10-20 本地候选实现。

“我的云盘｜配置”的原有分类和配置卡片保留，在“云盘配置”页新增“统一扫码登录”卡片，点击卡片才打开网盘选择，不在进入页面时自动弹窗。当前统一入口支持 UC（优汐）和夸克，其他网盘仍使用原配置项。

UC 使用原生二维码窗口，按现有 Android 插件的官方 CAS 协议申请二维码、等待手机确认并交换登录 Cookie；二维码可刷新，关闭后停止轮询。官网及本机默认解析下 CAS 主机 TLS 连接被中断，使用公共 DNS 返回的地址、保留主机名和标准证书校验后，原生 POST 接口成功返回令牌。因此仅 UC CAS 主机通过 HTTPS DNS 解析，未改全局代理、未关闭 TLS 校验。UC 登录令牌、服务票据和 Cookie 不写日志。

夸克仍打开 HTTPS 官网扫码页，用户确认后点击“完成登录”。登录 Cookie 按当前插件兼容编码写入 `spUtils.uc_ck/quark_ck`，删除重复的默认偏好旧值，避免注销后复用旧备份；保存成功后立即执行一次 WebDAV 拉取合并上传；未配置或已暂停时明确提示，不绕过重置保护。UC 同时保存原插件使用的 UC 服务票据。

保存后清除插件加载缓存，返回首页重新进入源后读取新登录态。UC 登录与 WebDAV 跨设备同步已验证；iPhone 已读取同步 Cookie 和真实选集。UC 正片播放仍受服务端客户端/会员限制，详见 `iphone-uc-drive-support.md`。

当前 Android 单测 86 项通过；其中 2 项校验插件字符串编码与 iPhone 解码夹具一致，以及拒绝空值、伪造键和换行注入。测试包采用现有本机调试签名，关闭代码压缩以加快本轮模拟器验证，已在 Kindle 保留数据覆盖安装。未提交或推送 Git。

## 模拟器验证

已在 MuMuPlayer 的 Kindle 实例确认：进入云盘配置后原有八项仍在，并新增统一扫码登录卡片；进入配置页没有弹窗；点击新卡片后才选择 UC 或夸克；UC 原生二维码已成功显示。二维码含临时授权信息，不保存到公开文档或 Git。用户已完成手机扫码授权，登录保存与同步至 iPhone 均已验证；真实正片播放仍受 UC 服务端限制。
